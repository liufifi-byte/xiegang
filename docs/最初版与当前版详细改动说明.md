# Decision Council：最初版与当前版详细改动说明

## 一、总体结论

这次改版不是简单地把“老算、老沉”换成“数学家、经济学家”，而是把产品从“五种固定立场共同辩论”，改成了“职业专家自主调研 + 动态议会职责 + 争议驱动讨论”的双层架构。

不过当前仍存在一个明显落差：架构已经升级，真实 Web Search 目前不可用，因此实际回答质量还没有完全达到设计目标。

## 二、总体变化

| 维度 | 最初版本 | 当前版本 |
| --- | --- | --- |
| 产品感觉 | 五个有性格的老朋友帮你想事 | 一场由职业专家组成的决策议会 |
| 人物 | 老算、老沉、小机、十年、反对 | 数学家、经济学家、心理学家、历史学家、艺术家、政治家 |
| 默认人数 | 固定五人 | 六选五，默认推荐五人，用户可修改 |
| 底层视角 | 人物和立场永久绑定 | 职业能力固定，议会职责动态分配 |
| 调研方式 | 程序提前替每人调用固定工具 | 专家 Agent 自己判断是否调用工具、调用什么 |
| Agent 架构 | 固定工作流，不是真正的 ReAct Agent | 有边界的 Reason → Act → Observe → Finish |
| 讨论轮次 | 固定三轮，全员重复参与 | 两轮起步，必要时进入第三轮 |
| 冲突方式 | 靠五个固定派别天然对立 | 从实际观点中提取核心争议 |
| 主持方式 | 专家互选议长 | 中立主持人整理争议与结论 |
| 证据 | 模型生成 evidence，真实性约束弱 | 用户信息、网页来源、计算、推断假设四类分离 |
| 可信度 | 专家自报 0–100% | 改成“判断基础有限/一般/较强” |
| 过程展示 | 发言流、轮次、工具记录 | 专家状态、Agent 调研路径、来源与核心争议 |
| 最终页面 | 当选议长综合 | 中立会议结论，不展示详细 Agent 轨迹 |

## 三、人物设定具体改动

### 3.1 老算 → 数学家

原来的老算是“理性派”，核心方法包括：

- 第一性原理；
- 期望值；
- 边际分析；
- 折现率；
- 强调“不给综合意见，只给数字”；
- 人格比较冷峻，像一个审问者。

现在的数学家保留了大部分理性分析能力，但范围更加清晰：

- 决策树；
- 期望值；
- 敏感性分析；
- 基准概率；
- 明确区分“事实数字”和“估计数字”；
- 必须找出哪个变量会使结论翻转；
- 明确禁止在数据不足时编造概率；
- 明确承认某些价值无法量化。

关键变化是：老算原来代表“理性立场”，现在数学家代表“量化方法”。数学家不再天然支持或反对某个方案。

这是一项合理的升级。因为“数学家”不应该等同于“凡事只看钱”，也不应该在数据缺失时强行给出精确答案。

### 3.2 老沉 → 动态下行风险职责

老沉原来是“保守派”，核心方法包括：

- 风险评估；
- 最坏情况；
- 反脆弱；
- 损失厌恶；
- 历史下行案例；
- 安全垫与生存优先。

现在没有一个专家完整继承老沉，而是将其拆成两部分：

- “下行风险审查”变成动态议会职责；
- 风险分析根据问题分配给经济学家、政治家、心理学家、历史学家或数学家等最合适的人。

例如：

- 买房的市场风险可能交给历史学家；
- 工作变动的执行风险可能交给政治家；
- 冲动消费的心理风险可能交给心理学家；
- 资产配置的下行风险可能交给经济学家或数学家。

这解决了“心理学家为什么一定是保守派”的错配问题。

但也损失了一点产品魅力：老沉作为“永远先问你输不输得起”的人物非常鲜明。当前的“下行风险审查员”更加专业，但记忆点不如老沉强。

### 3.3 小机 → 经济学家、艺术家与动态机会职责

小机原来是“机会派”，核心方法包括：

- 机会成本；
- 时间窗口；
- 沉没成本切割；
- 替代路径；
- 强调行动和不要错过。

现在这套能力被拆开：

#### 经济学家继承

- 机会成本；
- 边际收益；
- 真实替代方案；
- 激励机制；
- 可逆性和期权价值。

#### 艺术家继承

- 发现第三条路；
- 重构原有问题；
- 想象新的未来方案。

#### 动态议会职责继承

- “机会识别”根据当前议题分配给最合适的专家，而不是永远交给艺术家。

这样改的原因是：艺术家不应该天然等于“抓住机会”，经济学家也不应该只负责算钱。现在职业逻辑更加自洽。

### 3.4 十年 → 历史学家、心理学家与长期影响职责

十年原来是“长期派”，核心方法包括：

- 复利；
- 路径依赖；
- 身份认同；
- 十年后的回看视角；
- 短期得失与长期人生路径对比。

现在这套能力被拆开：

#### 历史学家继承

- 路径依赖；
- 长周期；
- 基准概率；
- 相似历史案例；
- 制度与时代差异。

#### 心理学家继承

- 身份认同；
- 价值观；
- 用户真正想成为怎样的人；
- 恐惧与真实意愿的区分。

#### 动态议会职责继承

- “长期影响审查”根据问题动态分配。

这一点比简单地把“艺术家=长期派”更合理。职业专家负责自己真正擅长的分析，长期视角则是本场会议中的动态职责。

### 3.5 反对 → 动态反方职责

原来的“反对”是一位固定的反共识派人物：

- 逆向思考；
- 流行偏见识别；
- 搜索历史翻车案例；
- 专门寻找主流共识的盲点；
- 在选举失败时会被兜底任命为议长。

现在取消了这个固定人物，改成动态的“反方挑战”职责。

例如：

- 艺术家可以质疑问题是否被限制成错误的二选一；
- 政治家可以质疑谁在推动用户做出决定；
- 心理学家可以质疑用户是否受到恐惧或社会期待驱动；
- 历史学家可以质疑当前叙事是否忽略历史基准；
- 数学家可以质疑关键概率是否根本没有依据。

这在逻辑上更合理，因为反方不再是“为了反对而反对”。

但这也会降低一点戏剧性。原来的“反对”是非常鲜明的内容角色，新版需要通过页面上的“本轮职责：反方挑战”把这种魅力补回来。

### 3.6 新增心理学家

心理学家是最初版本没有的完整能力，主要分析：

- 用户真正想获得什么；
- 用户真正害怕失去什么；
- 情绪是否正在代替事实；
- 是否存在确认偏误、损失厌恶、从众等偏差；
- 决策与身份认同、亲密关系之间的联系。

同时明确限制：

- 不进行心理疾病诊断；
- 不替用户定义感受；
- 不因为用户谨慎，就自动认为谨慎正确。

这使产品从“方案分析工具”向“个人重大决策产品”迈进了一步。

### 3.7 新增政治家

政治家主要负责：

- 利益相关者地图；
- 谁支持、谁反对；
- 谁握有决定权；
- 各方激励是否一致；
- 哪些条件可以通过谈判改变；
- 决策执行过程中会受到什么阻力。

它尤其适合以下场景：

- 接不接 Offer；
- 要不要离职；
- 是否创业；
- 婚姻和家庭协商；
- 合伙与股权；
- 买房时家庭成员之间的利益差异。

最初版本经常只分析“选择本身好不好”，政治家则补上了“这个选择能不能真正执行”。

## 四、底层 Agent 架构改动

### 4.1 最初版本：固定工作流模拟 Agent

最初版本虽然也有“工具调用”，但流程实际上由程序提前写好：

1. 五个人固定参加；
2. 程序给每个人固定分配两个工具；
3. 程序先替专家调用工具；
4. 把工具结果塞进提示词；
5. 模型生成立场、证据和总结；
6. 固定进行三轮讨论；
7. 最后进行议长选举。

例如老算固定获得：

- `web_search`
- `data_table`

老沉固定获得：

- `web_search`
- `historical_risk_lookup`

这不是严格意义上的自主 Agent，因为模型没有自行判断：

- 是否需要搜索；
- 当前缺少什么信息；
- 应该搜索什么；
- 搜索完是否继续；
- 是计算还是查询历史记录；
- 什么时候结束调研。

而且原来部分“专属工具”本质上只是不同搜索提示的包装，不是真正独立的数据源。

### 4.2 当前版本：局部自治 ReAct Agent

目前每个职业专家都有一个独立运行的 Agent 子图：

```text
Reason
  ↓
决定使用工具或结束
  ↓
Act：执行工具
  ↓
Observe：读取并整理结果
  ↓
再次 Reason
  ↓
Finish
```

模型现在理论上可以自己决定：

- 是否需要外部信息；
- 需要搜索什么关键词；
- 是否要调用计算器；
- 是否要查询用户历史；
- 当前证据是否足够；
- 是否应该继续一轮调研；
- 最终是支持、反对、暂缓还是有条件支持。

这部分已经不是纯角色扮演，而是真正实现了有边界的 ReAct Agent。

主要实现文件：

- `backend/app/agents/research_graph.py`
- `backend/app/agents/harness.py`
- `backend/app/agents/profiles.py`
- `backend/app/agents/tool_registry.py`

## 五、Agent Harness 改动

新版为 Agent 增加了统一运行环境，主要包括：

- 最大 Reason 步数；
- 最大工具调用次数；
- 单个工具超时；
- Agent 总运行时间；
- 允许调用的工具白名单；
- 搜索关键词中的隐私脱敏；
- 用户取消会议时终止 Agent；
- 工具异常后的降级；
- 证据数量上限；
- 调研路径事件；
- 结果结构校验；
- 不允许引用不存在的证据 ID；
- 单个专家失败不拖垮其他专家。

当前默认预算大致为：

- 最多 3 次 Reason；
- 最多 2 次工具调用；
- 单工具约 15 秒超时；
- 单 Agent 总计约 60 秒；
- 五个专家并行运行。

因此它是“有边界的 Agent”，不是让模型无限循环搜索。

## 六、工具系统改动

### 6.1 最初版本

工具由程序固定调用，每个议员拥有一个通用搜索工具和一个特色工具。

主要问题包括：

- 专家自己不能选择工具；
- 有些特色工具只是包装后的搜索；
- 即使问题不需要搜索，也会调用；
- 即使需要计算，也不一定调用正确工具；
- 工具结果与模型生成的“证据”没有严格绑定。

### 6.2 当前版本

当前统一为三个主要真实工具：

- `web_search`：查询公开网页；
- `calculator`：执行可复算的计算；
- `memory_search`：查询当前用户过去的相关决策。

不同专家具有不同权限：

| 专家 | Web Search | 计算器 | 用户历史 |
| --- | ---: | ---: | ---: |
| 数学家 | ✓ | ✓ | ✓ |
| 经济学家 | ✓ | ✓ | ✓ |
| 心理学家 | ✓ |  | ✓ |
| 历史学家 | ✓ |  | ✓ |
| 艺术家 | ✓ |  | ✓ |
| 政治家 | ✓ |  | ✓ |

重要区别是：现在“拥有工具”不代表必须调用，而是由 Agent 自己决定。

但当前 Web Search 供应商账户没有可用资源，所以代码能力已经存在，真实网页搜索暂时无法成功。黄金会议暴露的正是这个问题。

## 七、会议流程改动

### 7.1 最初版本

```text
理解议题
→ 五人并行调研
→ 第一轮全员辩论
→ 第二轮全员辩论
→ 第三轮全员辩论
→ 五人互选议长
→ 议长总结
```

主要问题：

- 每场固定三轮；
- 每轮五个人都发言，容易重复；
- 没有真正提取争议；
- 容易为了辩论而辩论；
- 议长选举有趣，但会增加等待时间；
- 当选专家的偏见可能进入最终总结；
- “反对”还被设置为选举失败时的默认议长。

### 7.2 当前版本

```text
理解决策
→ 推荐专家并允许用户调整
→ 五位专家独立自主调研
→ 第一轮：全员立场
→ 提取最多三个核心争议
→ 第二轮：相关专家交叉质询
→ 判断是否需要第三轮
→ 必要时进行收敛或压力测试
→ 中立主持人总结
```

主要变化：

1. 正式讨论改为两到三轮；
2. 第一轮五人都参加；
3. 第二轮只让与争议最相关的二到四人发言；
4. 如果第二轮已经充分收敛，直接总结；
5. 如果出现立场改变、用户补充、多个争议未解决或发言失败，再进入第三轮；
6. 快速形成共识时，也可以进行反共识压力测试；
7. 取消议长选举，改由中立主持人总结。

主要实现文件：

- `backend/app/graph/parliament.py`
- `backend/app/graph/nodes/council_rounds.py`

## 八、冲突机制改动

最初版本的冲突来自固定立场：

- 老算 vs 小机：数字没算清 vs 时间窗口快关闭；
- 老沉 vs 十年：短期安全 vs 长期复利；
- 小机 vs 反对：现在行动 vs 再等等；
- 老算 vs 老沉：期望收益高 vs 风险敞口大。

优点是天然具有戏剧性，但缺点是专家可能为了维持人设而强行反对。

当前版本的冲突来自实际分析结果：

- 对事实判断不同；
- 对同一证据解释不同；
- 对风险权重不同；
- 对用户目标理解不同；
- 对代价是否可接受判断不同；
- 对价值排序不同。

新版要求反驳必须指向：

- 对方的具体前提；
- 对方引用的数据；
- 对方的推理漏洞；
- 对方的价值排序。

这是从“立场型综艺辩论”向“决策型专家会议”的转变。

## 九、证据与可信度改动

### 9.1 最初版本

每位专家输出：

- 立场；
- 0–1 的 confidence；
- 三条 evidence；
- reasoning summary。

主要问题：

- confidence 是模型自己报告的，没有统计意义；
- evidence 只是模型输出字段，不保证真的来自工具；
- Few-shot 中本身包含大量精确数据，容易诱导模型模仿或编造；
- 搜索失败后模型仍可能凭记忆补充数字；
- 用户无法分辨哪些是事实、哪些是推断。

### 9.2 当前版本

当前将依据分成四类：

1. 用户明确提供的信息；
2. 真实网页来源；
3. 可复算的计算结果；
4. 明确标注的推断假设。

同时增加了以下规则：

- 网页来源必须有真实检索结果；
- 计算必须保存输入、公式和结果；
- 不存在的证据引用会被删除；
- 搜索失败时应进入降级状态；
- confidence 百分比不再作为主要用户展示；
- 改为“判断基础有限/一般/较强”。

不过目前代码只严格阻止了“引用不存在的证据”，还没有完全阻止正文出现无来源的精确说法。黄金会议里的“建议不超过总资产 15%”就是现存缺口。

因此，证据制度已经搭建出来，但还需要增加一层“无证据精确结论拦截”。

## 十、页面和用户路径改动

### 10.1 首页

已加入或调整：

- 斜杠 Logo；
- DECISION COUNCIL 品牌；
- 米色背景；
- 白色或浅米色输入区域；
- 精选场景卡片只保留问题标题；
- 点击精选场景后才显示“描述你的决策”和关键背景；
- 关键背景在逻辑上成为必要信息；
- 支持恢复正在进行的会议。

### 10.2 进入会议前

新增专家选择页：

- 六位职业专家；
- 系统默认推荐并勾选五位；
- 用户可以取消或替换；
- 每位专家展示推荐原因和分析方法；
- 选择结果写入会议。

相关页面：

- `frontend/app/council/setup/page.tsx`

### 10.3 会议室

新增或调整：

- 明确的返回首页箭头；
- 删除无意义的 Logo 下方圆圈；
- 修复返回与侧栏折叠混淆；
- 返回首页不等于结束会议；
- 首页显示“正在进行的会议”，可以再次进入；
- 页面默认定位到最新消息；
- 支持滚动阅读历史内容；
- 展示五位专家运行状态；
- 展示队列等待、任务领取、开始思考等真实状态；
- 专家完成一个就展示一个；
- 不再等待五个人全部结束才更新；
- “自主调研实况”可以收起；
- 搜索词、工具动作、来源数量可以展示；
- 当前讨论阶段可视化；
- 核心争议单独展示。

### 10.4 总结页

改为：

- 先给一分钟结论；
- 展示当前建议和建议强度；
- 展示关键理由；
- 展示共识与分歧；
- 展示下一步行动；
- 展示结论翻转条件；
- 可以展开查看整理后的分析依据；
- 不显示详细 ReAct 路径和内部 Agent 工作过程。

这符合“会议过程中展示 Agent 能力，最终页面回归用户决策本身”的原则。

## 十一、运行与多人使用能力改动

最初版本的任务执行依赖请求过程，页面断开、服务重启和超时处理都比较脆弱。

当前版本增加了：

- API 和 Worker 分离；
- 用户进入后自动创建并执行会议；
- 后台 Worker 自动领取任务；
- 数据库记录会议状态；
- SSE 实时推送；
- 页面断线重连；
- 正在运行会议恢复；
- 用户主动结束时取消任务；
- 单专家失败隔离；
- 超时降级；
- IP 与设备标识限流；
- 多个用户同时使用时的并发控制；
- LangGraph checkpoint；
- 事件持久化。

也就是说，产品已经从“本地演示页面”向“可支持多人使用的服务”前进了一大步。

## 十二、旧版思维模型如何被保留

虽然人物名称发生了变化，但最初五种思维方式没有全部删除，而是被重新安置：

| 最初思维模型 | 当前承载方式 |
| --- | --- |
| 理性派 | 数学家的专业内核 |
| 保守派 | 动态“下行风险”职责 |
| 机会派 | 经济学家能力 + 动态“机会识别”职责 |
| 长期派 | 历史、心理专业能力 + 动态“长期影响”职责 |
| 反共识派 | 动态“反方挑战”职责 |

这就是当前“双层专家议会”的核心：

> 用户表面看到的是数学家、经济学家、心理学家等有吸引力的职业人物；底层仍然确保理性、风险、机会、长期和反方五种视角不会缺席。

## 十三、当前版本相对最初版本的得失

### 13.1 明显改善

- 专业人物与思维方法更加一致；
- 真正增加了局部自主 Agent；
- 用户可以选择专家；
- 专家不会永久绑定支持或反对；
- 讨论围绕真实争议，而非机械重复；
- 工具、证据、推断开始分离；
- 最终结论更加中立；
- 多用户、恢复、取消和异常处理更接近正式产品；
- 技术上更能展示对 Agent、Harness、工作流和可观测性的理解。

### 13.2 有所减弱

- “老算、老沉、小机、十年、反对”的人格记忆点更强；
- 最初版本具有“几个老朋友帮你想事”的亲近感；
- 新版职业名称更加专业，但也更像常见 AI 专家产品；
- 动态职责目前在界面上的存在感还不够；
- 新版流程更加复杂，等待时间更长；
- Web Search 失效后，复杂 Agent 架构会暴露更多空转；
- 新版部分发言仍然偏向“专业报告”，还没有完全达到真人会议的冲突感；
- 当前代码保留了一部分旧版兼容路径，存在新旧逻辑并存的问题，维护成本较高。

## 十四、最终评价与后续重点

这次改版方向是正确的：它把项目从“有趣的多角色 Prompt 工作流”升级成了“固定议会工作流 + 局部自治专家 Agent”。

当前完成情况可以概括为：

- 产品架构完成度较高；
- Agent Harness 已经真实实现；
- 职业人设已经完成；
- 会议流程已经升级；
- UI 主路径已经改造；
- 真实证据能力尚未闭环；
- 职业人物的情绪魅力仍弱于老算、老沉时代。

下一阶段最重要的不是继续增加 Agent，而是补齐三件事：

1. 恢复真正可用的 Web Search；
2. 强制拦截无来源的精确结论；
3. 让每位职业专家说话更有“人格”，同时把动态的风险派、机会派、反方等职责在页面上明确表现出来。

这样才能同时保留新版的专业可信度与旧版的产品魅力。
