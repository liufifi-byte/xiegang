# 邪杠首页视觉与双入口改版设计

日期：2026-07-20

## 1. 目标

在保留原项目五议员议会、后端接口和议会流程的前提下，吸收“杠一杠”原型的品牌视觉与首页输入体验。首页需要同时服务两类用户：

1. 想从固定场景快速开始的用户；
2. 想直接输入任意问题的用户。

本次只调整首页，不修改议会过程页、总结页和后端协议。

## 2. 品牌区

首页顶部按以下顺序展示：

1. “斜杠”Logo 图片；
2. `DECISION COUNCIL` 英文眉题；
3. 原产品口号“先杠一杠，再下结论”。

Logo 从 `/Users/xinyiliu/Desktop/杠一杠-最新版本/网页原型/assets/logo.png` 复制到前端公开资源目录，页面不得依赖项目外路径。原有大字“邪杠会议室”不再单独展示，避免与图片 Logo 重复。

## 3. 视觉系统

首页采用朋友版的暖米白、深紫与珊瑚红配色，但不影响其他页面：

- 页面底色：暖米白 `#FFFAF6`；
- 内容卡片：白色或极浅米色；
- 主文字：深紫黑 `#251536`；
- 次级文字：灰紫 `#746D78`；
- 主按钮：深紫渐变；
- 小标题、焦点与强调：珊瑚红 `#EC403D`；
- 边框：浅米灰 `#E9DED8`。

首页颜色通过局部 class 实现，不全局替换现有 Tailwind 颜色，避免议会页和总结页发生非预期变化。

所有栏目标题统一使用与“你想和大家讨论什么？”一致的视觉规格：14px、粗体、深灰紫色。栏目标题不再使用全大写或过大的字间距。

## 4. 首页信息架构

首页顺序为：

1. 品牌区；
2. 精选场景；
3. 选中场景后的详情表单（条件显示）；
4. 通用场景输入卡。

### 4.1 精选场景

保留现有 8 个场景和两列/四列响应式网格。

每张卡片只显示决策名称：

- 买房
- 接 offer
- 跳槽
- 投资
- 创业
- 买黄金
- 买股票
- 买包

删除第二行的“居住、工作、职业、资产”等描述。选中状态使用深紫边框和浅紫背景。

### 4.2 场景详情表单

用户首次进入首页时，“描述你的决策”和“关键背景”均不渲染。

点击任一精选场景后：

1. 显示“描述你的决策”；
2. 显示“关键背景”；
3. 自动滚动到详情表单；
4. 决策输入框写入可编辑的默认值。

默认决策值按场景生成：

- 买房 → `要不要买房？`
- 接 offer → `要不要接这个 offer？`
- 跳槽 → `要不要跳槽？`
- 投资 → `要不要做这笔投资？`
- 创业 → `要不要创业？`
- 买黄金 → `要不要买黄金？`
- 买股票 → `要不要买这只股票？`
- 买包 → `要不要买这个包？`

“关键背景”标题不显示“必填”或“选填”，但提交校验要求内容非空。占位文案为：

> 请补充会影响决定的事实：你的目标、预算或收入、时间限制、家庭与地理约束、目前已有方案，以及你最担心的结果。

场景表单的“召集议会”仅在决策和关键背景都非空时启用。

用户切换场景时，决策值更新为新场景默认值，关键背景保留，避免误删已经输入的信息。

### 4.3 通用场景

删除现有“通用议会”介绍卡，替换为朋友版风格的输入卡。结构为：

- 标题：“你想和大家讨论什么？”；
- 最多 240 字的 textarea；
- 实时字符计数；
- 主按钮：“召集议会 →”；
- 卡片下方三个示例问题。

示例问题：

1. 要不要接受这份看起来稳定、但成长很慢的工作？
2. 现在买房，还是再等一年？
3. 该不该和合伙人继续做下去？

点击示例问题只填入通用输入框，不自动提交。通用输入框非空时按钮启用。

通用入口提交参数：

- `topic`：通用输入框内容；
- `category`：`general`；
- `background`：空字符串。

通用输入和精选场景详情使用独立状态，互不覆盖。用户可以在两种入口之间自由选择。

## 5. 交互与错误处理

- 请求进行中时，两个提交按钮均禁用并展示“召集中”和旋转图标，防止重复创建议会；
- 创建失败继续使用首页现有错误提示；
- 场景详情提交缺少背景时不弹浏览器警告，按钮保持禁用；
- 输入内容提交前统一 `trim()`；
- textarea 保留清晰的键盘焦点状态；
- 场景卡保留按钮语义和选中状态表达。

## 6. 响应式要求

### 桌面端

- 主内容最大宽度继续保持约 768px；
- Logo 不超过约 310px；
- 精选场景为四列；
- 通用输入卡居中展示。

### 移动端

- Logo 最大宽度约为屏幕的 75%～85%；
- 精选场景为两列；
- 场景详情和通用输入卡单列铺满；
- 主要按钮在窄屏上保持可点击宽度，不产生横向溢出；
- 页面不得出现横向滚动条。

## 7. 组件边界

本次主要修改 `HomeSceneTabs.tsx`，将内部划分为三个清晰区域：

1. 品牌区；
2. 精选场景与条件表单；
3. 通用输入卡。

如果单文件明显过长，可拆出仅供首页使用的 `BrandHeader`、`SceneDecisionForm` 和 `GeneralQuestionCard`，但不进行与本任务无关的重构。

## 8. 验收标准

1. 首页顶部正确显示本地 Logo、`DECISION COUNCIL` 和原口号；
2. 首页背景、卡片、按钮和文字符合指定配色；
3. 所有栏目标题字号、字重一致；
4. 精选场景卡只有一行决策名称；
5. 首次进入不显示场景详情表单；
6. 点击任一精选场景后显示表单并写入正确默认决策值；
7. 精选场景缺少关键背景时无法提交；
8. 通用输入卡可独立填写、使用示例问题并提交；
9. 两种入口都调用现有 `onSubmit`，不改变后端接口；
10. 前端生产构建和 TypeScript 检查通过；
11. 桌面和 390px 宽移动端完成视觉验收，无横向溢出。
