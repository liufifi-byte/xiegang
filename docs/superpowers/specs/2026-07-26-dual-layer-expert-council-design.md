# 双层专家议会产品设计

日期：2026-07-26  
状态：已确认，待实施计划  
适用范围：Decision Council 会议分析、讨论、证据与结果展示

## 1. 产品目标

Decision Council 面向个人重大决策用户。产品应让用户同时感受到：

1. 结论有事实、计算和清晰假设作为依据；
2. 专家具有鲜明、稳定、可记忆的人物形象；
3. 专家之间存在真实分歧，而不是五份相似报告；
4. 会议过程具有节奏和观赏性，适合一期传播；
5. 系统愿意暴露未知条件和能力边界，不伪装确定性。

体验优先级为“可信且有戏剧性，可信度略优先”。

## 2. 核心架构：双层专家议会

每位专家由两个相互隔离但连续工作的层组成。

### 2.1 内层：专业 Agent

内层负责理解目标、识别信息缺口、选择工具、核实事实、完成计算并形成专业判断。它采用有边界的 ReAct 循环：

`Reason → Act → Observe → Reason → Finish`

内层输出结构化结果，不直接把原始推理轨迹展示给普通用户。每位 Agent 必须受到步数、工具次数、总耗时和可调用工具白名单约束。

### 2.2 外层：议会角色

外层负责把专业判断转化为有辨识度的发言，并依据本场议会职责进行质询。外层可以改变表达方式和质询方向，但不能为了制造冲突修改事实、计算结果或专业结论。

### 2.3 中立主持人

主持人不是参选专家，也不通过专家自报的置信度选出。主持人负责：

- 提取核心争议；
- 决定每个争议的参与者；
- 判断是否进入第三轮；
- 区分事实争议、推理争议和价值排序；
- 形成中立、可执行的会议结论。

## 3. 人设深度

每位专家由“专业内核、稳定性格、动态议会职责”三部分组成。

| 专家 | 不可改变的专业内核 | 稳定表达特征 | 标志性问题 |
| --- | --- | --- | --- |
| 数学家 | 概率、变量、阈值、敏感性、期望值 | 冷静精确，主动指出不可量化部分 | 哪个变量变化会让结论翻转？ |
| 经济学家 | 机会成本、激励、资源配置、期权价值 | 务实敏锐，揭示隐性成本但不把金钱当成唯一价值 | 选择它真正放弃的是什么？ |
| 心理学家 | 价值观、偏差、情绪、身份、关系 | 温和但敢于指出自我欺骗，不进行医学诊断 | 这是你真正想要的，还是恐惧推动的？ |
| 历史学家 | 基准概率、周期、类比、路径依赖 | 沉稳克制，使用短类比并说明类比边界 | 类似选择过去通常如何演变？ |
| 艺术家 | 意义、想象力、问题重构、第三方案 | 大胆具体，不输出空泛理想主义 | 如果不接受现有选项，还能怎样定义问题？ |
| 政治家 | 利益相关者、权力、联盟、谈判空间 | 现实直接，但不把所有关系都解释成算计 | 谁希望你现在决定，谁从中受益？ |

动态议会职责从以下五项中按问题与专业适配度分配：

- 证据审计员；
- 下行风险审查员；
- 机会与替代方案探索员；
- 长期影响审查员；
- 反方质询员。

议会职责不得永久绑定某个职业，也不得覆盖专家的专业内核。

## 4. 冲突机制

系统不预设谁支持、谁反对。冲突必须从专家独立结论中发现，允许来自：

- 对事实的判断不同；
- 对同一证据的解释不同；
- 对风险的权重不同；
- 对用户目标的理解不同；
- 对可接受代价和价值排序不同。

主持人最多提取三个核心争议。每次反驳必须指向对方的具体前提、数据、推理或价值排序。不得通过重复观点、夸张立场或人身化语言制造戏剧性。

如果专家快速形成共识，系统执行一次反共识压力测试，检查最可能导致共识失效的条件。专家可以因新证据改变观点，并明确展示改变原因。

## 5. 会议流程与轮次

独立初判和调研不计入正式讨论轮次。正式讨论不少于两轮、最多三轮。

### 5.1 决策建模

系统提取：

- 决策问题和备选方案；
- 用户明确提供的事实；
- 用户偏好和价值排序；
- 尚未提供的关键条件；
- 可能需要核实的外部事实。

信息足够时直接开始，不强制用户完成长问卷。缺失条件默认用于条件分析，只有确实决定结论时才向用户追问。

### 5.2 独立初判

五位专家并行、互不可见地回答：

- 当前倾向；
- 核心理由；
- 最需核实的一项信息。

谁先完成就先展示谁，不等待五人全部完成。

### 5.3 针对性调研

系统汇总会影响结论的信息缺口，按需要调用网页搜索、计算器或用户信息，不强制每位专家调用工具。相同事实优先只核实一次，并进入公共证据池供其他专家引用。

### 5.4 第一轮：全员立场陈述

五位专家全部参与。每人提交：

- 当前倾向；
- 核心理由；
- 最重要的分析依据；
- 最担心的风险；
- 希望质询的具体判断。

主持人在本轮结束后提取最多三个核心争议。

### 5.5 第二轮：交叉质询

每个争议邀请最相关的二至四位专家交锋。每次发言必须至少完成一项：

- 反驳具体前提；
- 补充新证据；
- 指出价值排序差异；
- 提出替代方案；
- 因新信息调整立场。

未参与某个争议的专家仍保留在会议中。

### 5.6 第三轮：条件触发的收敛轮

满足以下任一条件时进入第三轮：

- 关键事实的解释仍冲突；
- 新证据可能改变结论；
- 至少一位专家改变立场；
- 用户补充重要信息；
- 多数专家过早达成一致，需要压力测试；
- 核心争议尚未形成可执行结论。

第三轮只处理剩余分歧、结论翻转条件和下一步行动，不得重复前两轮。若第二轮已经充分收敛，直接进入总结。

### 5.7 中立总结

主持人固定输出：

- 当前建议及建议强度；
- 最关键理由；
- 已形成的共识；
- 尚未解决的分歧；
- 结论使用的事实和假设；
- 用户下一步应核实或执行的事项；
- 哪些条件出现时应改变决定。

目标完成时间：

- 无大量搜索：70 至 100 秒；
- 需要第三轮或更多外部调研：100 至 150 秒。

## 6. 证据契约

所有影响结论的信息必须属于以下四类之一。

### 6.1 用户信息

仅包含用户明确提供的事实。系统不得擅自补全，也不得把推断写成用户事实。

### 6.2 网页来源

必须保存页面标题、发布者、发布时间、链接、所支持的具体判断和时效风险。只有真实检索成功且页面确实支持结论，才允许标记为网页来源。

### 6.3 计算结果

必须保存输入数据、公式、结果和采用的假设。精确数字必须能够从这些输入中复算。

### 6.4 推断假设

用于推进分析但尚未得到证实的判断。推断可以影响条件分析，但必须明确标识，不能伪装成事实。

### 6.5 硬约束

1. 没有来源，不得生成精确市场数据或历史事实；
2. 搜索失败时只能做条件分析，不得用模型记忆补充“最新数据”；
3. 专家必须引用公共证据池中的具体条目；
4. 证据只能支持推理中的具体部分，不能自动证明整个结论；
5. 四类依据必须在数据结构和页面展示中保持分离。

取消专家自报的置信度百分比。系统根据关键用户信息、外部事实、计算过程和反例检查情况，生成：

- 判断基础有限；
- 判断基础一般；
- 判断基础较强。

该等级评价依据完整性，不声称结论正确概率。

## 7. 展示设计

页面遵循“默认看会议，按需看依据”的原则。

### 7.1 会议进度

只展示用户可理解的阶段：

- 正在理解你的决策；
- 专家正在独立判断；
- 正在核实关键事实；
- 正在讨论核心争议；
- 正在形成会议结论。

普通流程不展示 Reason、Act、Observe、R0、Worker、队列和原始异常。完整 Agent 轨迹仅在会议进行中保留于独立的“Agent 运行记录”入口，用于技术展示和调试；会议完成后，该入口不得出现在最终总结页。

### 7.2 专家讨论流

主区域采用连续会议流。每条正式发言包含：

- 专家头像、职业和本轮议会职责；
- 80 至 150 字主要发言；
- 当前倾向；
- 判断基础；
- 分析依据数量；
- 是否改变过观点。

回应必须关联具体发言，使用户能理解谁在回答谁。

### 7.3 核心争议

每项争议展示参与专家、双方核心观点、已核实事实、未解决问题和当前收敛状态。点击争议可定位到对应讨论。

### 7.4 分析依据

每条重要发言提供默认收起的“查看分析依据”，按用户信息、网页来源、计算结果和推断假设分组。来源和依据应与具体发言关联，而不是统一堆放在页面底部。

### 7.5 最终结果

会议结束后先展示一分钟结论：

- 当前建议；
- 建议强度；
- 判断基础；
- 最关键理由；
- 下一步行动。

完整报告展开后展示目标、共识、分歧、方案代价、事实、假设、行动建议和结论翻转条件。

最终总结页不得展示详细 Agent 工作路径、ReAct 步骤、工具调用流水、内部状态节点或调试信息。总结中的“分析依据”只展示经过整理的用户信息、网页来源、计算结果和推断假设，不回放这些依据的内部获取过程。

## 8. 可信度与异常降级

系统内部评估：

- 证据完整性；
- 信息新鲜度；
- 假设依赖度；
- 争议解决度。

用户默认只看到判断基础及简短解释，详细指标按需展开。

异常不得使已完成内容丢失：

- 单个专家超时：其他专家继续，该专家可稍后补充；
- 搜索失败：转为基于用户信息的条件分析；
- 辩论超时：保留已完成讨论并使用现有内容总结；
- 总结模型超时：通过结构化结果生成基础总结；
- 页面刷新：恢复会议进度和阅读位置；
- 服务版本不一致：阻止新会议启动并给出维护提示。

任何内部错误都必须在服务边界转换为产品语言，不得向用户展示原始异常文本。

## 9. 产品魅力

### 9.1 人物记忆

专家拥有稳定头像、颜色、语言节奏和关注习惯，但不反复使用夸张口头禅。

### 9.2 观点变化

专家改变观点时展示原观点、新证据、新观点和仍保留的条件。观点变化是体现真实推理和会议推进的重要时刻。

### 9.3 用户介入

用户可在全员开场后和第二轮结束后：

- 补充事实；
- 回答专家问题；
- 点名专家解释；
- 要求两位专家直接交锋；
- 要求提前总结。

新增信息进入用户信息池，只重评受到影响的结论，不重跑整场会议。

### 9.4 可分享结果

生成默认脱敏的“我的决策议会”分享卡，包含决策主题、专家最终倾向、最激烈争议、最意外观点、最终建议和品牌标识。收入、资产、关系等背景默认隐藏，只有用户主动选择才可展示。

### 9.5 会议节奏

用户感受到的完整节奏为：

`专家亮相 → 独立判断陆续出现 → 核心争议形成 → 两至三轮讨论 → 观点变化或压力测试 → 形成结论`

## 10. 模块边界与数据流

系统拆分为以下独立模块：

1. 决策建模器：将用户输入转换为事实、偏好、未知条件和待核实事项；
2. 专家内核：运行各专业 Agent 并输出结构化判断；
3. 工具与证据层：执行搜索和计算，维护公共证据池；
4. 议会编排器：分配职责、提取争议并控制二至三轮讨论；
5. 中立主持人：决定第三轮条件并生成总结；
6. 展示适配层：将内部状态转换为用户可理解的进度、发言和依据；
7. 持久化层：保存会议状态、证据、发言关系、用户介入和恢复位置。

核心数据流：

`用户输入 → 决策模型 → 专家独立初判 → 针对性工具调用 → 公共证据池 → 第一轮全员发言 → 核心争议 → 第二轮质询 → 可选第三轮 → 中立总结 → 分享结果`

## 11. 验收标准

### 11.1 人物与冲突

- 隐去专家名字后，测试者仍能通过内容识别大多数职业；
- 同一问题不再出现五份结构和措辞高度相似的回答；
- 每场会议至少形成一次针对具体前提的质询；
- 无真实冲突时执行压力测试，不制造虚假争吵。

### 11.2 轮次与体验

- 每场会议至少两轮、最多三轮正式讨论；
- 第一轮五位专家全部参与；
- 第二、三轮发言必须产生新证据、新推理、新方案或立场变化；
- 已完成发言实时展示，不等待全部任务完成。

### 11.3 证据与可信度

- 精确外部数据均可追溯至网页来源或计算过程；
- 搜索失败时不生成伪精确最新数据；
- 所有依据均归入四类之一；
- 页面不出现专家自报的置信度百分比；
- 总结明确列出剩余假设和结论翻转条件。

### 11.4 稳定性

- 单个专家、工具或总结超时不导致整场会议失败；
- 页面刷新后能够恢复会议和阅读位置；
- 用户界面不出现原始异常、内部节点或队列术语；
- 最终总结页不出现 Agent 工作路径、ReAct 步骤或工具调用流水；
- 会议在目标时间范围内持续产生可见进展。

### 11.5 产品魅力

- 用户能说出至少一位专家的独特观点；
- 用户能复述会议正在争论的核心问题；
- 观点变化和压力测试可被清晰识别；
- 分享卡默认脱敏，并可独立理解本场会议的亮点。

## 12. 本期不包含

- 无限制自主浏览或无限轮次 Agent；
- 专家之间自由创建新工具；
- 将职业永久绑定为支持派或反对派；
- 通过模型自报百分比表达可信度；
- 为制造戏剧效果而预设争论结论；
- 商业化、付费和计费功能。
