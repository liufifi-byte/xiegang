# 快速确认页前端改版规范

## 1. 目标

把会前确认弹窗第一步从“完整简报展示”改成“快速确认页”。用户应能在 10 秒内完成两件事：

1. 扫描系统理解的决策目标、比较方案、分析重点和最终交付；
2. 内容准确时直接进入补充信息，内容不准确时展开输入框修改。

本次只调整信息结构、文案、视觉样式和第一步确认交互，不修改后端接口、预览数据结构、第二步问答逻辑或创建会议流程。

## 2. 涉及文件

- `frontend/components/council/TaskConfirmationStep.tsx`
- `frontend/components/council/DecisionPathModal.tsx`
- 新增或更新对应前端测试；优先新增 `frontend/tests/TaskConfirmationStep.test.tsx`

## 3. 当前问题

- `重点分析` 和 `最终交付` 使用双列布局，在 560px 弹窗内有效列宽不足，中文词组被强制断开。
- 决策目标字号和行距偏大，形成文字墙。
- 摘要内容分别使用卡片、胶囊、普通段落，缺少统一的扫描路径。
- 黄色 fallback 提示独占一行，切断摘要与确认动作。
- “这个任务理解准确吗？”、“按这个目标继续”和底部“补充关键信息”形成重复确认。
- 用户必须先点中间确认框，底部主按钮才可用，增加无意义步骤。

## 4. 最终信息结构

第一步从上到下固定为：

1. 两步进度；
2. 决策目标卡片；
3. 比较方案；
4. 重点分析；
5. 最终交付；
6. 可选的“修改任务理解”区域；
7. 固定语义的底部操作区。

不得再使用“重点分析 / 最终交付”双列布局。

## 5. `DecisionPathModal.tsx` 改动

### 5.1 弹窗宽度

保持现有 `max-w-[560px]`。本次问题来自内部编排，不通过盲目加宽解决。

### 5.2 标题文案

替换 header 内容：

- 眉题：`DECISION ROOM · 会前确认` 保留；
- 标题：`确认本次决策任务` 保留；
- 副标题从 `只补充会明显改变结论的信息` 改为 `请快速确认讨论方向，信息不准确时可以直接修改`。

### 5.3 第一页确认状态

第一步不再要求 `agreed === "confirmed"` 才能继续。

- 主按钮始终可点击；
- 点击主按钮即代表确认当前任务理解；
- 使用独立的 `editingBrief: boolean` 控制修正输入区是否展开；
- 用户输入修正内容后必须先点击“重新梳理”，不能绕过未应用的修改直接继续；
- 当修正输入为空或已经重新生成完成时，可以继续。

删除现有 `agreed` state 以及 `TaskConfirmationStep` 的 `agreed`、`onAgree` props，新增 `editingBrief`、`onEditingChange`。首次生成、关闭弹窗和重新生成成功后都将 `editingBrief` 重置为 `false`。不得修改发给后端的 `brief_confirmation: "confirmed"`。

定义 `hasPendingBriefFeedback = editingBrief && briefFeedback.trim().length > 0`。将其传给第一步，用于禁用“确认，继续补充信息”；用户必须先让修正内容重新生成，或清空修正内容，才能继续。

## 6. `TaskConfirmationStep.tsx` 改动

### 6.1 进度条

保留现有两步进度，但压缩底部间距：

- 外层从 `mb-5` 调整为 `mb-4`；
- 第一步保持深墨蓝实心圆；
- 第二步保持浅灰圆；
- 不新增复杂图标或动画。

### 6.2 决策目标卡片

目标卡片保持单卡，但降低文字密度：

- 外层建议：`rounded-xl border border-[#dbe5ef] bg-[#f5f8fc] px-4 py-3.5`；
- 删除粗重的 `border-l-4`，改成普通细边框；
- 标签使用 `text-[11px] font-bold text-[#607692]`，不再全大写；
- 正文使用 `text-[15px] leading-6 text-[#1d3049]`；
- 正文保留自然换行，不做 CSS 截断，不拆分数据内容；
- 若 `preview.fallback_used === true`，在卡片内部正文下显示小字：
  `当前内容根据已有信息生成，你可以在确认前修改。`
- fallback 文案样式：`mt-2 text-xs leading-5 text-[#8a6b25]`；不再显示独立黄色横幅。

### 6.3 比较方案

保留胶囊形式，但显示全部方案，不再 `.slice(0, 3)`：

- 区块标题：`比较方案`；
- 容器：`flex flex-wrap gap-2`；
- 标签：白底、浅边框、`text-xs`；
- 长方案允许自然换行，不能截断或省略。

### 6.4 重点分析

改为独立单列摘要行：

- 标题：`重点分析`；
- 内容使用项目提供的 `analysis_dimensions` 全量输出；
- 每一项渲染为轻量文字标签，不拼成一个长段落；
- 推荐容器：`flex flex-wrap gap-x-3 gap-y-2`；
- 每项前增加 4px 深墨蓝圆点；
- 字号 `text-sm`，行高 `leading-5`；
- 禁止使用 `sm:grid-cols-2`。

### 6.5 最终交付

改为独立单列摘要行：

- 标题：`最终交付`；
- 使用 `final_deliverables` 全量输出，不再 `.slice(0, 2)`；
- 表现方式与重点分析一致，但圆点使用较浅蓝色以区分；
- 不将数组提前 `join` 成长段落，避免词组在狭窄列中断裂。

### 6.6 修改入口

删除以下结构和文案：

- `这个任务理解准确吗？`
- `理解不准确？`
- `按这个目标继续`
- `✓ 理解正确，按这个目标继续`
- 调整区内的 `理解正确` 按钮

用一个轻量修改区替代：

- 摘要下方放置文本按钮：`信息不准确？修改任务理解`；
- 默认折叠；
- 点击后展开 textarea；
- 展开后按钮文案变为 `收起修改`；
- textarea 标签：`需要修正什么？`；
- placeholder：`例如：我更关注长期成长，不希望把短期薪资作为首要标准。`；
- 保留 `500` 字上限和字数计数；
- 主操作按钮：`重新梳理任务`；
- `briefFeedback.trim()` 为空时禁用。

修改区视觉上使用浅灰背景，不使用第二张重边框卡片。建议样式：

`mt-3 rounded-xl bg-[#f6f8fb] p-3`

### 6.7 底部操作区

保持左右布局，但缩短垂直距离：

- 外层：`mt-5 flex items-center justify-between gap-3 border-t border-[#e6eaf0] pt-4`；
- 左侧：`返回修改决策`；
- 右侧主按钮：`确认，继续补充信息 →`；
- 主按钮默认可用；
- 仅在正在重新梳理、正在创建会议，或存在尚未应用的非空修改内容时禁用；
- 禁用状态必须保持可读，不使用过低对比度。

## 7. 建议组件结构

`TaskConfirmationStep` 保持为一个组件，但把重复摘要样式拆成两个小型内部组件：

```tsx
function SummaryBlock(props: {
  title: string;
  items: string[];
  tone?: "primary" | "secondary";
})

function BriefEditPanel(props: {
  open: boolean;
  value: string;
  maxLength: number;
  onChange: (value: string) => void;
  onRegenerate: () => void;
  onClose: () => void;
})
```

不要新增全局状态、Context 或第三方 UI 依赖。

## 8. 第二步一致性

`DecisionQuestionsStep.tsx` 本次不重构，仅做以下一致性检查：

- 继续使用同一弹窗宽度；
- “上一步”返回第一步时，已填写答案不得丢失；
- 第一步修正并重新生成问题后，只保留仍然存在的 question id 对应答案；
- 第二步底部主按钮样式与第一步一致。

## 9. 响应式要求

- 360px 宽度下不能出现横向滚动；
- 比较方案和摘要标签必须自然换行；
- 底部两个按钮在窄屏允许上下排列，主按钮占满一行；
- 640px 以上维持左右操作布局；
- 弹窗内容超出视口时只滚动正文，header 保持可见。

## 10. 无障碍要求

- 保留 `role="dialog"`、`aria-modal="true"` 和标题关联；
- “信息不准确？修改任务理解”使用真实 `button`；
- 展开按钮提供 `aria-expanded`；
- textarea 必须有可关联的 `label`；
- 禁用按钮使用原生 `disabled`；
- 错误信息继续以文本呈现，不能只依赖颜色。

## 11. 测试与验收

至少覆盖以下前端测试：

1. 渲染目标、全部比较方案、全部分析维度和全部最终交付；
2. fallback 提示位于目标卡片内部，旧黄色横幅不存在；
3. 默认不显示 textarea；点击修改入口后展开；
4. 空修正内容时“重新梳理任务”禁用；输入内容后启用；
5. 默认状态下点击“确认，继续补充信息”直接调用 `onContinue`，不需要中间确认；
6. 存在未应用修改时不能直接继续；
7. 旧文案“这个任务理解准确吗？”和“按这个目标继续”不再出现；
8. 保留错误信息、返回操作和字数上限。

运行并通过：

```bash
cd frontend
npm run test
npx tsc --noEmit
npm run build
```

## 12. 不在本次范围

- 不改后端生成的 `decision_goal` 文本；
- 不修改 `DecisionPathPreview` 类型；
- 不更改问题数量、答案类型和自动跳题行为；
- 不引入动画库、图标库或新的设计系统；
- 不调整 Phase 7 Harness Feed；
- 不修改创建会议 API。

## 13. 完成标准

- 第一屏不再出现左右双列摘要；
- 用户从进入弹窗到继续只需要一次主按钮点击；
- 所有摘要数组内容完整展示；
- 在桌面和手机宽度下均无断列和横向滚动；
- 原有两步流程、重新生成、答案保留和创建会议行为不回归；
- 前端测试、类型检查和生产构建全部通过。
