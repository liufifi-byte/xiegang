# model-compare — 多模型对比技能（设计文档）

- 日期：2026-06-22
- 状态：已设计，待用户审阅
- 范围：ZCode 技能，用当前活跃模型跑固定探针并归档，支持横评

## 1. 背景与目标

用户每天在 ZCode 里通过 `/model` 切换不同模型试用，希望把这些试用的观察沉淀
成可对比、可回看的记录。约束：模型 API 只能通过 ZCode 配置访问，脚本无法直
连外部 API。

因此工具形态必须是 **ZCode 技能（skill）**，而非独立脚本：技能本身不调
API，只负责用「当前活跃模型」跑固定探针、记录、对比。

### 目标

- 用当前活跃模型跑 5 个固定探针，终端即时输出 + 追加归档
- 同一会话内多次 `/model` 切换，每次切换后跑一遍 → 自然形成多方对比素材
- 支持从档案抽取多次运行生成横评表
- 零外部依赖、零配置文件——一切由技能 + 固定的 probes.md 决定

### 非目标（明确排除）

- 不调外部 API、不写脚本直连 Anthropic
- 不让模型自报模型名（不可靠）
- 不做并发（当前活跃模型只有一个）
- 不做运行时配置——5 个探针固化在 `probes.md` 内，改测试题需要手动改源文件
- 不做长文本/工具调用/agent 场景评测——超出"快速识别模型差异"目标

## 2. 解决方案：ZCode 技能

### 2.1 文件布局

```
/Users/xinyiliu/ZCodeProject/skills/model-compare/
├── SKILL.md                  # 技能定义、工作流、归档规则
├── probes.md                 # 5 个固化探针（源文件，非运行时配置）
└── templates/
    └── entry.md              # 单次运行记录模板
```

运行时数据（不进 git）：

```
~/.model-compare/
└── log.md                    # 所有运行记录 + 历次 compare 归档
```

`~/.model-compare/` 路径选择理由：与 `oneday` 项目把数据放用户家目录的惯例
一致，避免污染代码仓库；如目录不存在，技能首次运行时创建。

### 2.2 与 `skills/llm-wiki/` 的风格对齐

- YAML frontmatter 用多行 `description: |`，末尾带「触发条件」段
- 自指用「AI」（不是 "the assistant" / "the model"）
- 步骤式工作流、fenced code 展示输出示例
- `${SKILL_DIR}` 引用同级文件（probes.md、templates/entry.md）

## 3. 工作流路由

用户激活技能时，AI 根据用户意图路由到三个工作流之一：

| 用户说什么 | 路由到 |
|---|---|
| "测一下这个模型" / "跑一遍探针" / "记录当前模型" / `/model-compare run` | **run** |
| "对比 opus 和 sonnet" / "横评这两个" / `/model-compare compare` | **compare** |
| "看历史" / "上次跑的是哪个" / "model-compare 都测过什么" / `/model-compare history` | **history** |

歧义处理：意图不明确时，问一句"你想 run / compare / history？"再继续。

## 4. 工作流：run

### 4.1 步骤

1. **问模型标签**：AI 说 "请问这次用的是什么模型？给个简短标签（例：opus-4.5、sonnet-4、glm-5.2）"，等用户回答。**不靠模型自报**。用户答非所问（空、过长 >20 字）则重问一次，再空则退出（exit 1）。
2. **加载探针**：读 `${SKILL_DIR}/probes.md`，按其分节取出 5 段探针 prompt。
3. **逐个跑探针**：探针按定义顺序跑。对每个探针：
   - 把探针 prompt 作为新消息发给当前活跃模型（即继续当前会话）
   - **拿到回答后立即在终端打印**：`[Probe N/5] <维度名>` + 原始回答
   - 把这条回答缓存到内存里（不落档，等全跑完一起追）
4. **追加到 `~/.model-compare/log.md`**：5 条全部跑完后，按 `templates/entry.md` 整段追加。包含：运行时间（ISO 8601, 本地时区）、模型标签、5 条探针的「维度名 + prompt 摘要 + 完整回答」。
5. **结尾告知用户**：告诉用户已归档 N 条，提示可以 `/model-compare compare` 横评。

### 4.2 错误处理

- 探针中途模型报错（context overflow、超时）：该探针记为 `[ERROR] <原因>`，继续跑下一个，不中断。
- `log.md` 不存在或为空：首次运行时创建 + 写入文件头（"# model-compare 运行档案\n\n"）。
- `probes.md` 读不到：报错退出（exit 1），提示文件丢失。

### 4.3 单次 run 不重复入档

如果用户在同一会话里对**同一模型标签**连续说"再跑一遍"，AI 提示"该标签已跑过，是否覆盖还是改用新标签？"，避免档案污染。

## 5. 工作流：compare

### 5.1 步骤

1. **确定对比对象**：用户列出 N 个模型标签（N≥2）。AI 在 `log.md` 里找每个标签**最近一次** run 记录（避免模型版本漂移造成误比）。
   - 找不到某标签：报错列出，退出（exit 1）。
2. **生成横评表**：按探针维度组织，终端打印一张表，每行一个 probe，每列一个模型。表内容是每个模型对该 probe 的回答摘录（前 ~80 字，超出截断 + …）。
3. **询问是否自动评分**：AI 问 "要不要我帮你判一下每个维度的胜者？（y/n）"。
   - **n（默认）**：跳过评分，归档表格到 `log.md` 末尾的「## 对比归档」段。
   - **y**：AI 跑一轮评判，对每个 probe 给出 1 个胜者 + 一句话理由，附在表格下方备注列。在 Log 顶端明确标注「⚠ 评分由当前活跃模型给出，仅作参考」。

### 5.2 评分纪律

- 评分模型本身**也是被测对象之一**时，AI 必须在评分前提示冲突，让用户决定要不要换模型评分。
- 评分时 AI 必须能引用每条回答的原文片段作为依据，不能空泛评价。

## 6. 工作流：history

简单列表输出 `log.md` 里所有 run 记录，每行一条：`日期 | 模型标签 | 探针数（=5）| 备注（如有 ERROR 标记）`。

compare 归档记录不在此列表显示，单独一行标注 "(N 条对比归档)"。

## 7. 5 个固定探针（固化在 `probes.md`）

| # | 维度 | 探针做什么 | 看什么 |
|---|---|---|---|
| 1 | 指令遵循 | 4 条强约束（80 字内 / 数字编号 / 不寒暄 / 主题指定）的写作题 | 几条违反 |
| 2 | 推理陷阱 | Simpson's paradox 类经典逻辑陷阱题 | 是否识破 |
| 3 | 代码生成 | 写最长上升子序列 O(n log n) 实现（默认 Python） | 正确性 + 复杂度 |
| 4 | 长上下文检索 | 1000 字文本里藏一句"密码是 7394"，问密码是多少 | 是否 retrieve 到 |
| 5 | 中文表达 | 开放创意题（描述 "AI 写代码这件事" 200 字内） | 文风 / 地道度 |

每段探针在 `probes.md` 里的格式：

```markdown
## Probe 1 — 指令遵循
<!-- 维度：指令遵循 -->
<!-- 看什么：是否每条约束都被遵守 -->

<完整 prompt 文本>
```

`probes.md` 是源码的一部分。换测试题需要手动编辑此文件——这是有意的约束，
保证不同模型、不同时间跑的是同一套题（可比性的根基）。

## 8. 数据格式

### 8.1 `templates/entry.md` — 单次 run 记录格式

```markdown
## [YYYY-MM-DDTHH:MM:SS±TZ] <模型标签>

- Probe 1 (指令遵循): <完整回答>
- Probe 2 (推理陷阱): <完整回答>
- Probe 3 (代码生成): <完整回答>
- Probe 4 (长上下文检索): <完整回答>
- Probe 5 (中文表达): <完整回答>

---
```

ERROR 探针的占位：`[ERROR] <原因>`

### 8.2 `~/.model-compare/log.md` 整体结构

```markdown
# model-compare 运行档案

## [timestamp] model-A
（...entry 模板...）

## [timestamp] model-B
（...entry 模板...）

<!-- compare 归档放文件末尾 -->
## 对比归档

### [timestamp] model-A vs model-B

| Probe | model-A | model-B | 胜者（可选） |
|---|---|---|---|
| 1. 指令遵循 | <摘录> | <摘录> | — 或 model-A |
| ...

> 评语（如有自动评分）：...

---
```

## 9. SKILL.md 写作约定

- 自指：「AI」（不用 "the assistant" / "the model"）
- 描述字段（frontmatter）：一句话描述 + 「触发条件」段（含正向 / 负向）
- 工作流路由用表格，前置检查和步骤用编号列表，输出示例用 fenced code
- `${SKILL_DIR}/probes.md`、`${SKILL_DIR}/templates/entry.md` 引用同级文件

## 10. 测试策略

技能本身是 Markdown，没有单测。验证方式按「可观察行为」划分：

| 验证项 | 怎么验 |
|---|---|
| 三个工作流路由正确 | 故意说模糊话，看是否回问 "run/compare/history？" |
| run 工作流追问模型标签、不靠模型自报 | 试用 "我不知道模型叫啥" 看是否重问 |
| 5 个探针都被跑到、按顺序 | 跑完一行行核对 entry |
| 探针报错不中断 | 故意触发 context overflow（超长 prompt）看是否记 [ERROR] 继续 |
| 首次运行能创建 `~/.model-compare/log.md` | 删档重来 |
| compare 找不到标签时报错 | 给个不存在的标签 |
| 自动评分默认不开、需 y/n 询问 | observe 是否询问 |
| 同标签重跑会提示覆盖/改名 | 同会话连测两次 |
