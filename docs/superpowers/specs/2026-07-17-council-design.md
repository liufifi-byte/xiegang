# 五贤阁（Council）设计文档

> 让决策慢下来，让思路站起来 — 5 个有不同思维模型的 AI 议员为你的真实决策展开一场思想辩论

- 日期：2026-07-17
- 状态：设计稿，待用户审阅
- 模型：GLM-5.2（智谱）

---

## 一、产品定位

### 一句话定义
用户提出一个真实决策，5 个有不同思维模型的 AI 议员分别独立调研、展开多轮辩论，最终产出多角度的议会纪要，帮助用户看见自己决策的多重视角。

### 核心反常识点
- **不是"AI 帮你查资料出报告"**——是"5 个 AI 互相吵架"
- **不是"AI 给你建议"**——是"AI 把所有角度摊开给你看"
- **议员不知道用户的"正确"答案**——他们不知道什么对用户最有利，只能从自己的思维模型出发
- **辩论是真的辩论，不是"轮流发言"**——议员会主动攻击其他议员的逻辑漏洞
- **议员的推理过程对用户完全透明**——你看到他为什么这么想、用什么证据、有没有偏见

### 用户主流程

1. **提案**：用户输入决策主题 + 关键背景
2. **分头调研**：5 个议员**并行**独立调研——彼此不可见
3. **初轮发言**：5 个议员各自给出立场 + 证据链（不评论他人）
4. **质询辩论**：3 轮辩论，议员之间互相质疑、反驳、补充
5. **议长选举**：5 议员互相选举出议长（含强制反对票 + 评分）
6. **议长总结**：当选议员输出议会纪要：共识、根本分歧、盲区、给用户的建议
7. **记忆归档**：本次议会结论存入跨议会记忆，下次相关决策时议员主动调用

| 十年 | `trend_research`（10 年+ 趋势数据） |
| 反对 | `contrarian_search`（专门搜反对意见和翻车案例） |

### 议员的"化学反应"（涌现式）

议员之间没有写死的冲突矩阵——冲突在调研阶段自然产生。但有**典型的强冲突对**：

| 冲突对 | 典型战场 |
|---|---|
| 老算 vs 小机 | 数据没看清 vs 窗口期错过 |
| 老沉 vs 十年 | 短期安全 vs 长期复利 |
| 小机 vs 反对 | "现在上" vs "等等看" |
| 十年 vs 反对 | "押注未来" vs "未来可能是陷阱" |
| 老算 vs 老沉 | 期望值正 vs 风险敞口大 |

## 三、议会流程编排

议会流程共 5 阶段，由 LangGraph 状态机驱动。

### 阶段一：提案与分解（主调度）

用户输入决策主题后，主调度 agent：

1. 判断主题属于"固定议题清单"还是"通用主题"
2. 提取议题的关键变量清单（例：买房 → 城市/总价/首付/贷款/持有期/收入稳定性）
3. 把"提案陈述 + 关键变量 + 用户相关历史记忆摘要"打包成**议会简报**，发给 5 个议员

### 阶段二：分头调研（5 议员并行）

**关键规则**：议员之间彼此不可见。

每个议员：
1. 思考自己需要什么信息（基于议题变量）
2. 调用自己的工具集（最多 5 次工具调用 / 总超时 60s）
3. 形成初轮立场：`for` / `against` / `neutral`，写出 3 条核心证据链
4. 把立场 + 证据提交给主调度

### 阶段三：初轮立场（用户可见）

- 每个议员**只说自己**，不评论他人
- 用户能看到每个议员的色块头像 + 立场表态 + 3 条核心证据
- 呈现顺序打乱（不让最激进或最保守的天然占先）
- 每条发言有"展开证据"按钮

### 阶段四：多轮质询（核心辩论）

**每轮结构**（固定 3 轮）：

```
第 N 轮:
  每个议员并行发言（基于上一轮所有人的发言）：
    - 可以选择：质询某议员 / 反驳某议员 / 补充自己立场 / 引入新证据
    - 不发言 = 弃权（表示同意他人观点）
  每轮结束主调度内部计算"议会张力"
```

**议会张力**（粗略规则）：
- 计算 5 个议员立场的离散度
- 有议员主动质询他人 → 加张力
- 多轮无新质询 → 减张力
- 阈值动态调

**用户干预**：
- 用户可点"插话"按钮追加信息
- 议员在下一轮接住用户的插话

### 阶段五：总结与归档

#### 5.1 议长选举

**三槽位强制发言**（缺一算弃权）：

```
【槽位 A：推荐某人】必须推荐某人（不能选自己）
  - 说明被推荐者的具体观点（必须引用原话）
  - 说明被推荐者的盲区

【槽位 B：自证偏见】
  承认自己的偏见类型和如何抵消

【槽位 C：综合方法】
  说明具体的综合 5 个视角的方法论
```

**评分机制**（主调度用轻量 LLM 评分）：
```
议长得分 = Σ(投票者权重 × 推荐理由质量分)
投票者权重 = 该议员的"判断力历史分"（初始 1.0，跨议会记忆累积）
推荐理由质量分 = 主调度评估：
  - 槽位 A 是否点名具体观点（有/无，0/1 分）
  - 槽位 B 是否识别真实偏见（具体/敷衍，0/1 分）
  - 槽位 C 是否有可执行流程（具体/抽象，0/1/2 分）
```

**强制反对票**：每个议员必须推荐他人（不能选自己），逼出有信息量的发言。

**兜底机制**（主调度检测到以下任一情况启用）：
- 票太分散（最高票 < 总票数的 30%）
- 推荐理由平均分 < 阈值
- 议员间出现"互投默契"

兜底策略：主调度直接任命**反对**为议长，公开声明理由（其本职就是审视主流叙事，最适合做元视角总结）。

#### 5.2 议长总结

当选议员以"议长身份"重新被调用（system prompt 临时追加议长守则）：

1. **共识区**——5 个议员都同意的部分
2. **分歧区**——核心争议点 + 各方立场
3. **盲区**——本次辩论没人提到的视角（议长主动补这块）
4. **给用户的建议**——基于综合，但明确标注"这是综合建议，不是正确答案"
5. **未决问题**——建议用户下一步去搞清楚的事

#### 5.3 记忆归档

本次议会结果存入跨议会记忆：
- 主题概要 + embedding
- 5 议员立场
- 共识 / 分歧
- 用户最终决策（如有）
- 1-5 星反馈（如有）

### 4.5 一轮议会时间预算（效果优先版）

```
议题分解                       10-15s
并行调研（5×，含工具）          60-90s
初轮发言（5 并行）              15-25s
辩论 3 轮（每轮 5 并行）        60-90s
议长选举（5 串行）              50-70s
议长总结                       30-45s
合计                            ~4-6 分钟
```

**优化策略**（不牺牲效果）：
- SSE 流式推送（体感加速）
- 轮内并行发言（每轮 5 个议员同时生成）
- 议员 system prompt 缓存（GLM-5.2 支持 prompt cache，省 30-50% token）
- 调研限时但不强切（每议员 60s 上限）

**不动的产品决策**：
- 调研工具调用上限 5 次/议员
- 辩论固定 3 轮
- 议长选举串行（保证互相评价质量）
- 议长总结完整输出（终产物）

### 4.6 跨议会记忆检索

## 五、议员 System Prompt 设计与 Few-shot 范例

### 5.1 System Prompt 六层结构

每个议员的 prompt 分层设计：

```
[第 1 层：身份与人格]   ~150 tokens
你是"老沉"，议会保守派议员...

[第 2 层：思维模型]     ~300 tokens
你的思维框架：风险评估 / 反脆弱 / 损失厌恶...

[第 3 层：当前任务]     ~200 tokens
用户正在决策：{topic}
关键变量：{variables}

[第 4 层：行为约束]     ~200 tokens
- 调研阶段最多 5 次工具调用
- 初轮发言不评论其他议员
- 辩论阶段必须引用其他议员的具体观点
- 选举阶段必须三槽位完整

[第 5 层：跨议会记忆]   ~动态 tokens
检索到的相关历史记忆片段...

[第 6 层：few-shot]     ~300 tokens
1-2 个该议员的发言范例
```

总计 ~1200-1500 tokens 静态 + 动态上下文，GLM-5.2 prompt cache 友好。

### 5.2 关键 Prompt 工程原则

**1. 强制结构化输出**：用 LangGraph `with_structured_output()` + JSON Schema：
```json
{
  "stance": "for | against | neutral",
  "confidence": 0.0-1.0,
  "evidence": [
    {"claim": "...", "source": "...", "strength": "high | medium | low"}
  ],
  "reasoning_summary": "..."
}
```

**2. 角色固化**：
- 负面清单（"你不是助手，你是审问者"）
- 立场锚定（开头第一句就表态，不能"先两边分析"）
- 语言风格锚（每个议员有标志性句式）

**3. 反漂移机制**：
- 每轮 prompt 重发（不靠 context 累积）
- 自我核查（每轮发言后议员自评"我有没有偏离 X 视角"，< 0.7 则重新生成）

### 5.3 Few-shot 范例

每个议员预置 1-2 个发言范例作为锚点。以下展示各议员的核心范例：

**范例 1：老算（理性派）**

议题示例："要不要接某创业公司 CTO offer？现金少 40%，但给 2% 股权。"

```
【立场】against
【confidence】0.72

【3 条核心证据】

证据 1：股权期望值计算
2% 股权的期望价值 ≈ 公司 5 年后退出估值 × 2% × 成功率。
- 若按 20 亿退出（乐观），期望值 = 4000 万 × 成功率
- 行业创业公司 5 年成功率约 10-15%（数据来源：PitchBook 2024）
- 期望值约 400-600 万，10 年期 IRR ≈ 5%
- 现职安全路径同期 IRR 约 12-15%（工资+晋升+股票）
结论：期望值跑输现职 7-10 个百分点。

证据 2：折现率不当
对方给的"股权对标 X 千万"是退出时的名义价值，未折现。
按 5 年期折现率 10% 算，现在值 ≈ 名义价值 × 0.62。
如果对方说"股权值 4000 万"，实际现在值约 2500 万。

证据 3：缺乏流动性补偿
2% 股权无流动性（5 年内无法变现）。
学术上私人股权流动性折扣 30-50%。
真实价值再砍 1/3，约 1700 万。
比现金少的 40%（约 32 万/年×5=160 万）其实就差 1500 万的 1/10 量级。

【推理小结】
纯粹从数字看，这笔股权不划算。除非退出估值上调到 50 亿以上，
或对方愿意补流动性条款（回购权/优先清算），才值得考虑。
```

**反面范例**（绝对不能这样写）：
```
我觉得这个 offer 看起来不错也有挑战。每个人情况不同，
建议你综合考虑自己的家庭情况、风险偏好、职业规划等因素再做决定。
```

**范例 2：老沉（保守派）**

议题示例："手上有 200 万闲钱，要不要 All-in 买 BTC？"

```
【立场】against
【confidence】0.85

【3 条核心证据】

证据 1：你输不起的金额
200 万是你说的"闲钱"，但 BTC 历史最大回撤 -83%（2018）、
-77%（2022）。83% 回撤意味着 200 万跌到 34 万。
- 你家庭年收入多少？能否在不卖币的情况下扛过 3 年？
- 孩子教育/父母医疗的储备是否独立于这 200 万？

证据 2："All-in" 这个措辞本身就是红旗
任何要求 All-in 的策略都违反分散原则。纳西姆·塔勒布在
《反脆弱》中明确反对"生存优先"的资产做高波动暴露。
分散的 BTC 配置上限，建议 ≤ 流动资产 5%。
200 万全部押注，相当于你把家庭资产负债表暴露在单一资产风险下。

证据 3：历史相似场景的复盘
2017 年末、2021 年初，都有"这次不一样"的叙事推动散户 All-in。
结局：-83% 回撤 + 长达 2-3 年的套牢期。
你这次的理由是不是也在"这次不一样"的谱系里？

【推理小结】
不是 BTC 不能买，是 All-in 永远错。把 200 万压低到 10-30 万
做试探仓，是我能接受的最激进建议。
```

**范例 3：小机（机会派）**

议题示例："要不要在 35 岁读 MBA？"

```
【立场】for
【confidence】0.65

【3 条核心证据】

证据 1：窗口期正在关闭
35 岁读 MBA vs 38 岁读 MBA，差别巨大：
- 35 岁毕业 37，招聘市场对"应届 MBA+10 年经验"仍有溢价
- 38 岁毕业 40，市场开始问"为什么这个年纪才读 MBA？"
再推迟 3 年，机会成本不是学费，是整个职业天花板的位移。

证据 2：不做的代价
不做 MBA 的替代路径是什么？
- 在原公司继续晋升：行业增速放缓，你估计多久到下一个级别？
- 跳槽：卡学历的天花板公司你碰过几次？
MBA 不是"学习"目的，是"通行证"目的。这个通行证会越来越贵。

证据 3：沉没成本切割
"已经工作了 10 年，再回去读 2 年是不是浪费？"
不对。读 MBA 是新投资，不是重复过去 10 年。
沉没成本不应该反向影响新决策。

【推理小结】
时间窗口比 MBA 学位本身更重要。如果要读，今年就要申请，
明年是另一种决策。
```

**范例 4：十年（长期派）**

议题示例："要不要从大厂跳槽到中型公司做技术负责人？"

```
【立场】neutral，倾向 for
【confidence】0.55

【3 条核心证据】

证据 1：10 年后回看
如果做了这个选择，10 年后你会怎样？
- 大厂路径：技术专家 → 高级专家 → 资深 → 可能管理层，也可能被优化
- 中型公司路径：技术负责人 → 也许 CTO → 也许共同创业 → 也许失败
10 年后回看，中型公司路径方差更大但上限更高。
关键问题：你是不是那种"上限更重要"的人？

证据 2：复利视角
技术负责人的能力增长曲线：
- 前 2 年：陡升（从执行到决策）
- 第 3-5 年：缓升（体系搭建）
- 第 6-10 年：复利期（经验+人脉+行业判断）
大厂里前 2 年的陡升会更陡，但复利期被分工切碎。

证据 3：身份认同
你 10 年后会怎么描述自己？
- "我是大厂的高级工程师"——身份被绑定在公司
- "我是某某公司的技术负责人"——身份属于自己
纳西姆·塔勒布的反脆弱框架：第二种身份反脆弱性更强。

【推理小结】
短期看是跳槽决策，长期看是"你想成为什么样的人"的决策。
如果你的身份认同需要大厂光环做支撑，就别跳。
如果你已经有独立的内在身份，跳。
```

**范例 5：反对（反共识派）**

议题示例："要不要买房？"

```
【立场】against
【confidence】0.60

【3 条核心证据】

证据 1：买房是社会主流叙事，但社会共识常错
"必须买房"在中国是 2003 年后才形成的强共识。
- 1998 年房改前，租房是主流
- 日本 1991 年后买房共识崩盘，跌了 20 年
- 德国/瑞士 50% 人口终身租房，社会运转良好
"必须买房"不是永恒真理，是 20 年的特定叙事。

证据 2：你的论证里有没有盲点
请检查你自己的论据里有没有这些社会主流话术：
- "租房没有归属感" —— 心理学研究反驳：归属感来自社交而非房产证
- "钱闲着不如买房" —— 流动性本身就是价值，房产流动性差
- "丈母娘要求" —— 把别人的价值观看作自己的需求
如果你引用的全是这类话术，需要警惕。

证据 3：历史翻车案例
2007 年美国买房共识顶峰，次年崩盘。
2017 年中国"房住不炒"提出前夜是另一个共识顶峰。
2024 年全球房价进入调整期。
共识顶峰往往就是反转起点。

【推理小结】
我不是说你不能买房。我是说：你"必须买房"的论证里，
有没有多少是你自己的思考、多少是社会植入的共识？
把后者剔除后再决定。
```
