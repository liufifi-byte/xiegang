# 专家长文本回复设计

日期：2026-07-30  
状态：已完成设计，待用户审核后实施

## 1. 背景

最初“老算、老沉、小机、十年、反对”版本的回复较长，通常包含明确结论、三条证据链、计算或案例、风险和推理小结。当前职业专家版本虽然生成了 `thesis`、风险、假设、未知条件、结论翻转条件和下一步动作等结构化字段，但会议正文只展示 `thesis`，而正式辩论提示词又把单条发言限制为 80–150 字。

这导致当前体验出现三个问题：

1. 分析内容被拆散后没有重新组织成完整发言；
2. 正式辩论没有注入完整的职业人格、分析方法和语言范例；
3. Web Search 失败时，降级结论进一步缩短为一两句话。

前端正式发言不存在正文截断，因此本次改动以生成和后端数据映射为主。

## 2. 设计目标

- 恢复旧版“长、完整、有条理”的阅读体验；
- 保留职业专家的人物合理性和新版证据契约；
- 每位专家的发言必须体现其独特分析方法；
- 不把同样的长文在两到三轮中机械重复；
- 不因为追求篇幅而允许无来源的精确市场事实；
- 保持五位专家并行运行和现有会议流程。

## 3. 方案比较

### 方案 A：只放宽字数

将 80–150 字改为 300–500 字，不调整结构。

优点是修改简单；缺点是容易生成更长的空话，不能解决结构化字段未展示和职业人格未进入辩论的问题。

### 方案 B：分层长文与结构合成（采用）

根据会议阶段设置不同篇幅，把 Agent 的结构化分析合成为完整发言，并将完整职业宪法注入正式辩论。

优点是能够同时恢复内容深度、人物区分和会议节奏；缺点是需要调整提示词、数据映射和测试。

### 方案 C：页面展示短摘要，点击后阅读完整报告

主讨论流继续保持短发言，每位专家提供独立长报告入口。

优点是页面简洁；缺点是用户默认仍然感受不到专家内容深度，不符合本次“每条回复更完整”的目标。

## 4. 回复长度与结构

### 4.1 独立判断

目标长度：350–600 字。

固定包含：

1. 我的判断；
2. 我是怎么分析的；
3. 最关键的依据；
4. 最担心的风险；
5. 当前未知或使用的假设；
6. 结论翻转条件；
7. 用户下一步动作。

独立判断应综合展示 `thesis`、`key_risks`、`assumptions`、`unknowns`、`reversal_conditions` 和 `next_actions`，而不是只展示 `thesis`。

### 4.2 第一轮立场陈述

目标长度：250–400 字。

必须包含：

- 明确倾向与核心理由；
- 一项最重要的分析依据；
- 一个关键风险；
- 对另一位专家某项判断的具体质疑；
- 当前结论成立的条件。

### 4.3 第二轮交叉质询

目标长度：180–300 字。

只围绕一个核心争议展开，必须引用或准确复述另一位专家的具体前提，并完成反驳、补充证据、指出价值排序差异或提出替代方案中的至少一项。

### 4.4 第三轮收敛

目标长度：150–250 字。

不得重复前两轮，只说明：

- 剩余分歧的类型；
- 当前更成立的条件判断；
- 结论翻转条件；
- 用户下一步动作。

## 5. 人格注入

每轮正式辩论都必须获得当前专家的：

- 专业身份；
- 分析方法；
- 必须检查的问题；
- 表达风格；
- 标志性问题；
- 专业边界；
- 腔调范例。

动态议会职责只增加本轮审查重点，不覆盖职业人格。

模型应模仿范例的锐度、结构和人物辨识度，但不得复制范例中的数字、年份或事实。

## 6. 证据规则

- 外部事实必须来自真实网页来源；
- 精确计算必须能够复算；
- 用户信息、网页来源、计算结果和推断假设继续分开；
- 没有来源时可以给出完整的条件分析，但不能用模型记忆补充最新数据或精确历史统计；
- 搜索失败不等于只返回一句“信息不足”，专家仍需基于用户信息完成风险、假设、翻转条件和下一步分析；
- 页面中的“查看分析依据”继续默认收起。

## 7. 数据与展示

### 7.1 独立判断正文

新增统一的公开发言渲染方法，将结构化 Agent 结果合成为 Markdown 风格纯文本，写入 transcript 的 `content`。

### 7.2 正式讨论正文

继续使用 `reasoning_summary` 作为正式发言字段，但提示词根据轮次规定结构与目标长度。

### 7.3 前端

正式发言继续完整展示，不增加 `line-clamp`。保留现有气泡和折叠依据，不新增复杂页面。

## 8. Web Search 验收

Web Search 不能只验证接口返回成功，还需验证：

1. 返回至少一个带标题、链接和正文摘要的结果；
2. 来源链接可进入证据账本；
3. 查询包含当前日期或明确的时效要求；
4. 搜索失败时产生可理解的降级状态；
5. 黄金等时效性问题不能把搜索词误展示成已经核实的事实；
6. 供应商返回部分不完整结果时，记录过滤数量，避免“HTTP 200 但最终零来源”难以诊断。

2026-07-30 本地实测：

- GLM Web Search 返回 HTTP 200；
- 供应商返回 5 条黄金相关结果；
- 当前项目过滤后得到 1 条包含标题、链接和正文的有效来源；
- 说明搜索服务已经恢复，但结果过滤与来源质量仍需在实现阶段补充测试。

## 9. 测试范围

- 独立判断正文包含所有必要分析段落；
- 三轮提示词具有不同字数与任务要求；
- 六位专家的完整人格配置进入辩论提示词；
- 前端不截断正式发言；
- 无网页来源时不出现未经支持的精确市场数据；
- Web Search 真实冒烟测试返回至少一个可打开来源；
- 现有 Agent Harness、超时、取消和并行执行测试保持通过。

## 10. 不在本次范围内

- 不改变两到三轮的议会流程；
- 不增加新的专家；
- 不重做会议室视觉设计；
- 不增加新的外部搜索供应商；
- 不在最终总结页展示详细 ReAct 工作路径。
